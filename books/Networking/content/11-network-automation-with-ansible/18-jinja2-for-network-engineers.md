# Chapter 18 — Jinja2 for Network Engineers

## Why Jinja2 Is Your Network Config Compiler

Resource modules cover common features, but every real network has vendor-specific QoS policies, route-maps, VRFs, or campus port templates that are far cleaner to render as deterministic text. **Jinja2** turns structured YAML data models into vendor-exact CLI configurations.

## Core Syntax Primitives

| Construct | Syntax | Purpose |
| :--- | :--- | :--- |
| Expression | `{{ hostname }}` | Print a variable or filter result |
| Statement | `{% for v in vlans %}...{% endfor %}` | Control flow (`for`, `if`, `set`, `macro`, `include`) |
| Comment | `{# Generated by Ansible #}` | Documentation omitted from rendered output |
| Whitespace trim | `{%- if x -%}` | Strip leading/trailing whitespace and blank lines |

## Essential Filters for Network Engineers

Combine built-in Jinja2 filters with `ansible.utils.ipaddr` (backed by Python `netaddr`) so you never calculate subnet masks or wildcard masks by hand again:

```jinja2
{# Convert CIDR notation (e.g., 10.10.20.1/24) into IOS IP, netmask, and OSPF wildcard #}
interface {{ intf.name }}
 description {{ intf.description | default('UNASSIGNED') | upper }}
 ip address {{ intf.cidr | ansible.utils.ipaddr('address') }} {{ intf.cidr | ansible.utils.ipaddr('netmask') }}
 no shutdown
!
router ospf {{ ospf.process_id }}
 network {{ intf.cidr | ansible.utils.ipaddr('network') }} {{ intf.cidr | ansible.utils.ipaddr('hostmask') }} area {{ intf.ospf_area | default(0) }}
```

### High-Value Filter Reference

| Filter | Input → Output |
| :--- | :--- |
| `default('fallback', true)` | Replaces undefined or empty values safely |
| `ansible.utils.ipaddr('address')` | `'10.1.1.1/30'` → `'10.1.1.1'` |
| `ansible.utils.ipaddr('netmask')` | `'10.1.1.1/30'` → `'255.255.255.252'` |
| `ansible.utils.ipaddr('hostmask')` | `'10.1.1.1/30'` → `'0.0.0.3'` |
| `ansible.utils.ipaddr('network')` | `'10.1.1.1/30'` → `'10.1.1.0'` |
| `selectattr('role', 'equalto', 'uplink')` | Filters a list of interface dicts by attribute |
| `sort(attribute='id')` | Guarantees deterministic ordering (prevents noisy diffs!) |

## Writing Clean, Reusable Macros

Use Jinja2 `{% macro %}` blocks to avoid duplicating repetitive configuration stanzas across interfaces or BGP peer groups:

```jinja2
{% macro bgp_neighbor(peer) -%}
 neighbor {{ peer.ip }} remote-as {{ peer.asn }}
 neighbor {{ peer.ip }} description {{ peer.desc }}
 {% if peer.password is defined -%}
 neighbor {{ peer.ip }} password {{ peer.password }}
 {% endif -%}
{%- endmacro %}

router bgp {{ bgp.local_asn }}
 bgp router-id {{ bgp.router_id }}
{% for peer in bgp.peers | sort(attribute='ip') %}
{{ bgp_neighbor(peer) }}
{% endfor %}
```

> [!TIP]
> Always sort loops (`| sort(attribute='id')`) and trim blank lines cleanly with `{%- ... -%}`. Deterministic whitespace ensures `git diff` and Ansible `--diff` highlight real intent changes instead of random ordering noise.
