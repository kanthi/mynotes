# fg

## Overview

`fg` is a shell builtin that resumes a stopped or background **shell job** in the **foreground**, returning terminal control (stdin, stdout, and keyboard signals like `Ctrl+C` / `Ctrl+Z`) to it. Pair it with `Ctrl+Z`, `jobs`, and `bg` for interactive multitasking inside a single terminal session.

## Syntax

```bash
fg [job_spec]
```

If `job_spec` is omitted, `fg` resumes the current job (`%+`).

## Common Job Specifications

| Spec | Meaning |
|------|---------|
| *(none)* / `%+` / `%%` | The current (most recently suspended/backgrounded) job |
| `%-` | The previous job |
| `%N` | Job number `N` (as shown by `jobs`) |
| `%name` | Job whose command line starts with `name` (e.g., `%vim`) |
| `%?str` | Job whose command line contains `str` |

## Key Use Cases

1. Temporarily suspend an editor (`Ctrl+Z`) to run a shell check, then jump right back in (`fg`)
2. Pull a noisy backgrounded command (`./server &`) back to the foreground so `Ctrl+C` can stop it
3. Unblock a background job that paused with `Stopped (tty input)` because it asked for a password or prompt

## Safety

- Jobs belong strictly to the **current shell**—if your SSH session drops without `tmux` or `screen`, foreground and background jobs tied to that TTY receive `SIGHUP` and terminate.
- Always check `jobs` before running `fg %N` if multiple jobs have finished, as job numbers can shift.

## Examples with Explanations

### Suspend an editor with `Ctrl+Z`, check something, and resume

```bash
vim /etc/nginx/nginx.conf
# Press Ctrl+Z to suspend vim
sudo nginx -t
fg              # jumps right back into vim
```

### Pull a specific background job forward by number or name

```bash
./dev-server &
jobs -l
fg %1           # or: fg %./dev-server
# Now Ctrl+C sends SIGINT to dev-server
```

### Switch back and forth between two suspended tasks

```bash
jobs
fg %1
# Ctrl+Z
fg %2
```

### Answer a hidden prompt from a backgrounded job

```bash
sudo apt upgrade &
# [1]+  Stopped   sudo apt upgrade   (waiting for TTY input)
fg %1
```

Background jobs attempting to read stdin from the terminal are automatically paused with `SIGTTIN` until brought to the foreground.

## Notes & Pitfalls

- Do not use `fg` inside non-interactive shell scripts—job control (`set -m`) is disabled by default in scripts; use `wait PID` instead.
- For long-running remote tasks or production services, prefer `tmux`/`screen` (so sessions survive disconnects) or `systemctl`/`systemd-run` (for daemons).

## Related Commands

- `bg` — resume a stopped job in the background
- `jobs` — list active and stopped jobs in the current shell
- `kill` (`kill %1`) — send a signal to a job
- `tmux` / `byobu` — persistent terminal multiplexing across disconnects
