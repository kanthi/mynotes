# wg & wg-quick

## Overview

`wg` and `wg-quick` configure and inspect **WireGuard**—the fast, modern, kernel-native VPN built into Linux (5.6+). `wg` manages live WireGuard interfaces, keys, and peer endpoints; `wg-quick` wraps `wg` and `ip` to bring entire tunnels up and down from `/etc/wireguard/*.conf` files (including IP addresses, routes, DNS, and `systemd` integration).

```bash
sudo apt install wireguard-tools   # Debian/Ubuntu
sudo dnf install wireguard-tools   # Fedora/RHEL
```

## Syntax

```bash
sudo wg [show [interface]]
sudo wg <genkey | pubkey | genpsk>
sudo wg-quick <up | down> <interface_or_conf>
```

## Common Commands

| Command | Description |
|---------|-------------|
| `sudo wg show` | Show all active WireGuard interfaces, listening ports, peers, handshakes, and transfer bytes |
| `wg genkey` | Generate a new Curve25519 private key |
| `wg pubkey` | Derive the corresponding public key from stdin |
| `wg genpsk` | Generate an optional post-quantum pre-shared key (`PresharedKey`) |
| `sudo wg-quick up wg0` | Bring up `/etc/wireguard/wg0.conf` (interface, IPs, routes, DNS) |
| `sudo wg-quick down wg0` | Tear down `wg0` and clean up routes/DNS |
| `sudo systemctl enable --now wg-quick@wg0` | Persist tunnel across reboots via systemd |

## Key Use Cases

1. Inspect whether a VPN peer has completed a handshake and is passing traffic (`wg show`)
2. Generate Curve25519 key pairs cleanly without writing private keys to disk prematurely
3. Bring up site-to-site or client VPN tunnels (`wg-quick up wg0`)
4. Hot-reload peer changes onto a live interface without dropping active connections (`wg syncconf`)

## Safety

- Keep `/etc/wireguard/*.conf` and private key files mode `0600` (`umask 077`).
- When editing `AllowedIPs = 0.0.0.0/0` on a remote cloud server, make sure you exclude your own SSH management IP or keep a console fallback—routing all traffic into an unconfigured tunnel will lock you out.

## Examples with Explanations

### Generate a private + public key pair safely (`umask 077`)

```bash
(umask 077 && wg genkey | tee private.key | wg pubkey > public.key)
```

Sets `0600` permissions automatically before creating `private.key`.

### Check live tunnel status and peer handshakes

```bash
sudo wg show
sudo wg show wg0 latest-handshakes
```

Look for `latest handshake:` (within the last ~2–3 minutes when active) and increasing `transfer: X MiB received, Y MiB sent`.

### Bring a tunnel up/down and enable on boot

```bash
sudo wg-quick up wg0
sudo systemctl enable --now wg-quick@wg0
sudo wg-quick down wg0
```

### Reload peers without dropping existing VPN sessions (`syncconf`)

```bash
sudo wg syncconf wg0 <(sudo wg-quick strip wg0)
```

Applies newly added peers from `/etc/wireguard/wg0.conf` live without tearing down `wg0`.

### Watch handshakes live during troubleshooting

```bash
watch -n 1 sudo wg show
```

### Minimal `/etc/wireguard/wg0.conf` server snippet

```ini
[Interface]
Address = 10.10.0.1/24
ListenPort = 51820
PrivateKey = <SERVER_PRIVATE_KEY>

[Peer]
PublicKey = <CLIENT_PUBLIC_KEY>
AllowedIPs = 10.10.0.2/32
```

## Notes & Pitfalls

- WireGuard is **silent by design**: if a handshake fails (wrong key, blocked UDP port `51820`, or NAT), it sends no error packet—check `sudo tcpdump -ni eth0 udp port 51820` and `wg show` (`transfer: 0 B received`).
- For a server acting as a VPN gateway, enable IP forwarding (`sysctl -w net.ipv4.ip_forward=1`) and configure NAT (`nft`/`iptables`) in `PostUp`/`PostDown` or your host firewall.

## Related Commands

- `ip` (`ip addr`, `ip route`) — inspect `wg0` addresses and routes
- `tcpdump` — verify UDP packets reaching `ListenPort`
- `sysctl` — enable `net.ipv4.ip_forward` for routing gateways
- `nmcli` — manage WireGuard via NetworkManager on desktops
