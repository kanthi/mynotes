# pv

## Overview

`pv` (Pipe Viewer) monitors data moving through a shell pipeline, displaying a **progress bar, elapsed time, current throughput, total bytes, and ETA**. It is invaluable for long `dd` disk images, database restores, `tar` archives, and `nc`/`ssh` transfers that otherwise give zero feedback until completion.

```bash
sudo apt install pv   # Debian/Ubuntu
sudo dnf install pv   # Fedora/RHEL
```

## Syntax

```bash
pv [options] [file...]
command1 | pv [options] | command2
```

## Common Options

| Option | Description |
|--------|-------------|
| `-s SIZE` | Set expected total size (e.g., `10G` or bytes) so `pv` can calculate `%` and ETA |
| `-p` / `-t` / `-e` / `-r` / `-a` / `-b` | Show progress bar, timer, ETA, current rate, average rate, bytes (all on by default when `-s` is given) |
| `-N LABEL` | Prefix the progress line with a custom name |
| `-c` | Use cursor positioning so multiple `pv` instances in one pipeline display stacked bars |
| `-L RATE` | Throttle transfer speed (e.g., `-L 20M` for 20 MiB/s) |
| `-W` | Wait until the first byte arrives before starting the timer/ETA |
| `-n` | Numeric percentage output (one number per line—great for dialog/scripts) |
| `-d PID` | Watch file descriptors of an **already-running** process (modern `pv`) |

## Key Use Cases

1. Monitor throughput and ETA when streaming compressed backups into `psql` or `mysql`
2. Throttle a heavy copy or network transfer (`-L 50M`) so it doesn't saturate disk I/O or bandwidth
3. Track `tar` or `dd` progress when piping over `ssh` or `nc`
4. Compare input vs. compressed output throughput with stacked bars (`-cN`)

## Examples with Explanations

### Stream a file with automatic size detection and ETA

```bash
pv ubuntu-server.iso > /dev/sdb
```

When `pv` reads a regular file directly, it detects the file size automatically without `-s`.

### Monitor a compressed database restore (with known size)

```bash
pv -s "$(stat -c '%s' backup.sql.gz)" backup.sql.gz | gzip -dc | psql -U postgres appdb
```

### Estimate total size for a `tar` pipeline

```bash
tar -cf - /var/www | pv -s "$(du -sb /var/www | awk '{print $1}')" | zstd > www.tar.zst
```

Gives an accurate progress bar and ETA for directory trees.

### Throttle a pipeline to protect production bandwidth

```bash
pv -L 25M large-archive.tar.zst | ssh backup-host 'cat > /backups/large-archive.tar.zst'
```

Caps the SSH transfer at 25 MiB/s.

### Multi-stage labeled progress bars

```bash
pv -cN raw big.tar | zstd | pv -cN zstd > big.tar.zst
```

Displays two live stacked bars—one for input read speed and one for compressed output speed.

### Attach `pv` to an already-running `cp` or `gzip` process

```bash
pv -d "$(pgrep -n gzip)"
```

## Notes & Pitfalls

- When `pv` sits in the middle of a pipe (`cmd | pv | cmd2`), it cannot guess the total size unless you pass `-s SIZE`; without `-s`, it shows bytes transferred, elapsed time, and throughput instead of an ETA.
- Remember that `pv` writes its progress UI to **stderr**, so stdout remains clean for downstream pipes (`|` or `>`).
- On modern GNU `dd`, `status=progress` covers simple disk copies natively, while `pv` shines for arbitrary multi-stage pipelines and rate-limiting (`-L`).

## Related Commands

- `dd` (`status=progress`) — block copy with built-in progress
- `rsync` (`--info=progress2`) — file sync progress
- `progress` — attach to running coreutils (`cp`, `mv`, `tar`)
